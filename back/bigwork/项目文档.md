# 汽车大数据分析平台 — 项目文档

## 一、项目概述

本项目是一个**汽车大数据分析平台**，从汽车之家网站爬取汽车参数数据，经过清洗后存入数据仓库，通过 Spring Boot 后端提供 REST API，前端页面可视化展示分析结果。

**核心架构特点：**
- **Hive 优先、H2 降级**：优先连接 Hive 数据仓库，连接失败自动降级到 H2 内存数据库（从 CSV 加载数据）
- **多维度数据分析**：基础统计（4项）、分类维度（13项）、排序度量（9项）、业务关联（17项）
- **文件上传与报表**：支持 CSV/Excel 文件上传解析、数据预览、全维度分析报表生成与下载

## 三、Java 源文件说明

### 3.1 核心框架

| 文件 | 说明 |
|------|------|
| `CarsApplication.java` | Spring Boot 启动类，`@SpringBootApplication` |
| `DataSourceConfig.java` | 数据源配置核心：Hive 优先、H2 降级策略。首次连接时检测 Hive 可用性（3秒超时），不可用则自动切换 H2；运行时 Hive 连接失败也会降级到 H2 |
| `HiveConfig.java` | Spring 配置类，提供 `ConnectionProvider` Bean，委托 `DataSourceConfig` 获取连接 |
| `DataInitializer.java` | 实现 `CommandLineRunner`，启动时从 classpath 的 `car_clean.csv` 加载数据到 H2；若数据源为 Hive 则跳过加载 |

### 3.2 基础统计

| 文件 | 说明 |
|------|------|
| `CarsService.java` | 4 个基础查询方法：品牌排名、价格分布、能源分布、级别分布。通过 `ConnectionProvider` 获取连接，每次查询后关闭连接 |
| `CarsController.java` | 5 个 REST 接口：数据源状态 + 4 个基础统计接口，路径 `/api/cars/` |

### 3.3 高级分析（分类 + 排序）

| 文件 | 说明 |
|------|------|
| `AdvancedCarsService.java` | 22 个方法：9 个分组维度 + 4 个离散化分类 + 9 个排序度量。排序支持 `order`（asc/desc）和 `limit`（1~100）参数 |
| `AdvancedCarsController.java` | 22 个 REST 接口，路径 `/api/cars/advanced/`，分组用 `/group/{dimension}`，排序用 `/sort/{metric}?order=desc&limit=10` |

### 3.4 业务关联分析

| 文件 | 说明 |
|------|------|
| `BusinessAnalysisService.java` | 17 个方法，覆盖 5 大业务维度：品牌×级别×指导价、上市时间×能源类型、排量×燃油标号×马力、车身结构×座位数×级别、变速箱×发动机配置 |
| `BusinessAnalysisController.java` | 17 个 REST 接口，路径 `/api/cars/biz/`，按维度分组：`/brand-level-price/`、`/energy-trend/`、`/power-match/`、`/space-config/`、`/powertrain/` |

### 3.5 文件上传与报表

| 文件 | 说明 |
|------|------|
| `FileDataService.java` | 文件解析（CSV 用 OpenCSV，Excel 用 Apache POI）、数据导入（匹配 cars 表结构则导入 cars 表，否则导入 generic_data 表）、数据预览、表结构查询 |
| `ReportService.java` | 全维度分析报表生成（汇总基础统计 + 分类维度 + 业务关联）、保存为 CSV 文件（BOM 头兼容 Excel）、报表列表查询、报表文件读取 |
| `DataController.java` | 7 个 REST 接口：文件上传、数据导入、数据预览、报表生成/保存/列表/下载，路径 `/api/data/` |

## 五、工作流程

整个项目分为 **4 个阶段**：

```
1. URL采集          2. 数据爬取           3. 数据清洗           4. 可视化分析
collect_urls.py  →  main.py + crawler  →  data_clean.py  →  Spring Boot + 前端
   ↓                    ↓                     ↓                   ↓
series_urls.xlsx     data.csv            car_clean.csv       index.html
                                         ↓
                               ┌── Hive 可用 ──→ 导入 Hive 表
                               └── Hive 不可用 → 加载到 H2 内存库
```

### 阶段 1：URL 采集（collect_urls.py）
- 遍历汽车之家 A~Z 字母页面，提取所有车系 ID
- 生成车系 URL 列表，写入 `series_urls.xlsx`

### 阶段 2：数据爬取（main.py + crawler.py）
- 读取 `series_urls.xlsx` 中的 URL
- 调用汽车之家参数 API 获取每款车的详细参数
- 支持异步并发爬取（aiohttp）和同步串行模式（requests）
- 支持断点续爬（checkpoint.json）和失败重试（failed.json）
- Cookie 轮换机制防止被封
- 输出原始数据到 `data.csv`

### 阶段 3：数据清洗（data_clean.py）
- 读取 `data.csv`（11列原始数据）
- 执行以下清洗操作：
  - 价格标准化：`12.28万` → `12.28`
  - 上市时间解析：拆分为 year/month/season
  - 质保拆分：`三年或10万公里` → years=3, km=10
  - 发动机拆分：`1.5L 115马力 L4` → 排量/马力/类型
  - 变速箱编码：`6挡手自一体` → gear_count=6, type=AT
  - 车身拆分：`5门5座SUV` → doors/seats/body_type
  - 能源/燃油编码：汽油→1, 纯电动→0
- 输出清洗后数据 `output/car_clean.csv`（22列结构化数据）

### 阶段 4：可视化分析（Spring Boot + 前端）

**数据源策略（Hive 优先、H2 降级）：**

1. 应用启动时，`DataSourceConfig` 先尝试连接 Hive（3秒超时）
2. Hive 可用 → 使用 Hive 数据仓库（需提前导入 car_clean.csv）
3. Hive 不可用 → 自动降级到 H2 内存数据库，`DataInitializer` 从 classpath 的 `car_clean.csv` 加载数据
4. 运行时 Hive 连接失败 → 自动降级到 H2

**后端 API 分层：**

- **基础统计**（CarsController）：4 个基础分析接口 + 数据源状态接口
- **高级分析**（AdvancedCarsController）：13 个分类维度 + 9 个排序度量
- **业务关联**（BusinessAnalysisController）：5 大业务维度 × 17 个关联分析接口
- **数据分析**（DataController）：文件上传、数据导入、预览、报表生成/保存/下载

**前端展示（index.html）：**

5 个 Tab 页：
- 基础统计：品牌排名、价格分布、能源分布、级别分布
- 分类维度：13 个分组/离散化分类
- 排序度量：9 个数值排序
- 业务关联：5 大维度关联分析
- 数据分析：文件上传、数据预览、报表生成

### 6.1 Hive 数据仓库（优先）

| 配置项 | 值 |
|--------|-----|
| Hive Server2 地址 | `121.4.19.133:10000` |
| JDBC URL | `jdbc:hive2://121.4.19.133:10000/default` |
| 用户名 | `ubuntu` |

**Hive 建表 SQL：**

```sql
CREATE TABLE cars (
    brand STRING,
    level STRING,
    energy_code STRING,
    energy_name STRING,
    fuel_grade STRING,
    launch_date STRING,
    launch_year INT,
    launch_month INT,
    launch_season STRING,
    price_wan DOUBLE,
    warranty_years INT,
    warranty_km_wan DOUBLE,
    displacement_L DOUBLE,
    horsepower DOUBLE,
    engine_type STRING,
    is_electric STRING,
    gear_count INT,
    trans_type STRING,
    doors INT,
    seats INT,
    body_type STRING,
    body_structure STRING
)
ROW FORMAT DELIMITED
FIELDS TERMINATED BY ','
STORED AS TEXTFILE;
```

**数据导入 Hive：**

```bash
# 将清洗后的 CSV 上传到 HDFS
hdfs dfs -put output/car_clean.csv /user/hive/warehouse/cars/

# 或在 Hive CLI 中加载
LOAD DATA LOCAL INPATH 'output/car_clean.csv' OVERWRITE INTO TABLE cars;
```

### 6.2 H2 内存数据库（降级）

| 配置项 | 值 |
|--------|-----|
| JDBC URL | `jdbc:h2:mem:carsdb;DB_CLOSE_DELAY=-1;MODE=MySQL` |
| 用户名 | `sa` |
| 密码 | （空） |

- 启动时由 `DataInitializer` 自动从 `car_clean.csv` 加载数据
- CSV 文件打包在 JAR 内（`src/main/resources/car_clean.csv`）
- 仅在数据源为 H2 时执行加载，Hive 可用时跳过

### 6.3 数据源切换逻辑

```
应用启动
  ↓
DataSourceConfig.getConnection() 首次调用
  ↓
tryHive() — 3秒超时测试连接
  ├── 成功 → activeSource = "hive"
  └── 失败 → activeSource = "h2"，DataInitializer 加载 CSV
  ↓
后续每次 getConnection()
  ├── "hive" → getHiveConnection()
  │     └── 失败 → 降级到 H2
  └── "h2" → getH2Connection()
```

## 九、注意事项

1. **Cookie 必须配置**：爬虫依赖汽车之家的登录 Cookie，未配置则无法获取数据。Cookie 可能过期，需定期更新。
2. **并发控制**：默认并发数为 1，可在 `.env` 中调整 `MAX_CONCURRENCY`。过高并发可能触发反爬。
3. **数据源自动切换**：后端启动时自动检测 Hive 可用性，不可用时降级到 H2。前端页面顶部显示当前数据源状态。
4. **Hive 连接超时**：Hive 连接测试超时为 3 秒，如果 Hive 服务器响应慢可能导致误判为不可用。
5. **断点续爬**：爬虫支持断点续爬，中断后重新运行 `main.py` 会自动跳过已完成的 URL。
6. **数据一致性**：清洗后的 CSV 字段顺序需与 Hive 表结构一致，否则导入会错位。
7. **文件上传大小**：最大支持 100MB 文件上传，在 `application.properties` 中配置。
8. **报表存储**：生成的分析报表保存在 `reports/` 目录下，CSV 格式带 BOM 头，可直接用 Excel 打开。
9. **H2 数据持久性**：H2 为内存数据库，应用重启后数据会重新从 CSV 加载。通过文件上传导入的数据重启后会丢失。
